# 6 核验与可能过期

[核验（Source Check）](../../GLOSSARY.md)回到证据的来源，确认当初记下的摘录是否仍在。它是确定性的：不调用 LLM，也不判断记忆的论断是否成立。判断由智能体完成，并用附证、取代或撤回表达（第 3 章）。

## 核验结果

| 值 | 含义 |
|---|---|
| `match` | 相符：摘录仍在来源中 |
| `changed` | 已变：来源还在，但摘录找不到了 |
| `unreachable` | 不可达：文件不存在、网页取不到 |
| `unverifiable` | 不可核验：来源本就无法回查（`conversation`、`command`） |

`unverifiable` 不算问题，不产生可能过期标记。

## 匹配规则

来源内容与摘录都按第 1 章的规则归一化（Unicode NFC，连续空白折叠为一个空格，去掉首尾空白），然后做**精确子串**查找。按内容锚定：摘录还在就是相符，与文件其余部分是否改动无关。不做模糊匹配，不设相似度阈值。

## 各来源的核验方式

### 文件

1. 定位项目根：证据的 `project`（或其别名组中的某个标识）须与本设备当前解析出的项目相同（第 1 章「定位项目路径」），项目根即当前项目的根。**本设备定位不到该项目时不核验**，沿用缓存中已有的结果（没有则视为未核验）。
2. 读 `<项目根>/<path>`：
   - 文件不存在或不可读：`unreachable`。
   - 不是合法 UTF-8：按有损解码（非法序列替换为 U+FFFD）后匹配。
   - 否则按匹配规则判 `match` 或 `changed`。
3. 行号提示 `line` 只用于先在附近查找，不影响结果。

**mtime 捷径**：缓存记下核验时文件的 mtime 与大小；再次核验时二者都未变，直接沿用缓存结果，不读文件。

### 网页

只在 `verify` 时进行，`search`、`get`、`review`、`context` 从不联网。

1. 对 `url` 发一次 HTTP GET：跟随最多 5 次重定向，超时 10 秒，不带 cookie 与认证信息。
2. 状态码非 2xx、DNS 失败、连接失败或超时：`unreachable`。
3. 响应为 HTML 时，去掉 `<script>`、`<style>` 元素及其内容，去掉其余标签，解码 HTML 实体，得到文本；其他文本类型直接用响应体；非文本类型（图片、PDF 等）判 `changed`。
4. 按匹配规则判 `match` 或 `changed`。

需要执行 JavaScript 才能渲染内容的页面会判为 `changed`；这是确定性核验的已知局限。

### 对话、命令输出

直接返回 `unverifiable`，不回查（`transcript_path` 只作参考），不重跑命令。

## 时机

| 时机 | 核验什么 | 联网 |
|---|---|---|
| 写入（`record`、`corroborate`） | 不核验 | 否 |
| `search`、`get` 返回前 | 惰性核验：结果中记忆当前引用的 `file` 证据 | 否 |
| `verify` | 所选记忆当前引用的全部证据；`include_web: false` 时跳过网页 | 是 |
| `review`、`context` | 不核验，只读缓存 | 否 |

不设后台进程，不定时核验。server 模式下核验只在客户端进行，server 没有核验代码路径（第 8 章）。

## 核验缓存

核验结果是本设备的观察，不进日志（[ADR 0002](../adr/0002-event-log-is-the-source-of-truth.md) 的事实来源只有日志）。存在 `cache/` 中，可删，删后重新核验即可。

- 按证据 id 保存最近一次结果：`result`、`at`（核验时间），`file` 证据另存 mtime 与大小。
- 只保留最近一次，不留历史。
- 文件格式由实现决定。
- 清除（第 2 章）时整个 `cache/` 随之删除。
- 远程模式的设备同样在本设备保存核验缓存，存放位置见第 8 章。

## 可能过期

[可能过期（Stale）](../../GLOSSARY.md)是从本设备核验缓存推导出的标记，不是生命周期状态：不改变可见性，不写日志，almanac 不自动处置。

### 判定

一条记忆带可能过期标记，当且仅当：

1. 取它**最近一次带来证据的事件**：最近一次 `corroborated`；没有附证则为 `memory_recorded`。
2. 该事件带来的证据中，至少一条在本设备缓存中的最近结果为 `changed` 或 `unreachable`。

- 只看最近一批证据：附证表示写入方已对此前的证据作出判断，所以附证后，更早证据的核验结果不再产生标记。
- 被清除的证据不参与判定。
- 缓存中没有结果的证据视为没有问题。
- 标记附带导致它的证据与结果，格式见第 3 章的 `Stale`。

### 由谁处置

智能体或人重读来源后：

| 判断 | 操作 |
|---|---|
| 记忆仍成立 | `corroborate`，以来源当前的摘录为新证据；标记随之消失 |
| 情况变了 | `record` 新记忆并 `supersedes` 旧的 |
| 本就错了 | `retract` |
