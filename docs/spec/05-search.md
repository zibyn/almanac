# 5 检索

`search`（第 3 章）只做确定性、可解释的词法检索加结构化过滤；判断相关与否由智能体多轮检索完成（[ADR 0003](../adr/0003-no-llm-or-embeddings-in-the-core.md)）。检索分两层：**分析器**把文本切成词元，**索引**负责倒排与打分。两层之间的接口是「文本 → 词元序列」这个纯函数，可各自替换。

## 分析器

自写的组合分析器，索引与查询用同一个。

### 步骤

1. **归一化**：Unicode NFKC（全角转半角），再小写化。
   这只用于检索；证据指纹与核验用的是第 1 章的 NFC 归一化，两者互不影响。
2. **切段**：按字符类把文本切成三种段：
   - **汉字段**：连续的 CJK 统一表意文字。
   - **词段**：连续的字母、数字，以及夹在其间的连接符 `_` `-` `.` `::` `/`（如 `append_only_log`、`tokio::spawn`、`v0.3.5`、`http/2`）。
   - 其余字符（空白、标点）：丢弃，不产生词元。
3. **汉字段** → `jieba-rs` 的 `cut_for_search`，开启 HMM。
4. **词段** → 标识符拆分，输出整体与各部分：
   - 整体：去掉首尾连接符后的整个词段（`tokio::spawn`）。
   - 部分：按连接符切开，再按大小写边界拆 camelCase（`getUserById` → `get` `user` `by` `id`；`HTTPServer` → `http` `server`）。大小写边界在第 1 步小写化**之前**判断。
   - 只输出长度 ≥ 1 的部分；与整体相同的部分不重复输出。

### 两个字段

| 字段 | 内容 | 作用 |
|---|---|---|
| `terms` | 汉字段的 jieba 词元 + 词段的整体与部分 | 主字段 |
| `bigrams` | 每个汉字段的重叠二元组；只有一个字的汉字段输出这个字 | 兜底新词与误切（如 jieba 把「缺字段」切成 `缺字` `段`，`bigrams` 里仍有 `字段`） |

两个字段都保留真实的词元位置。

v0.1 不提供用户词典，也不内置补充词表：jieba 切碎或误切的新词（「智能体」「缺字段」）由 `bigrams` 兜底召回。

### 规则版本号

本章分词规则带一个版本号，改动任何分词规则都必须递增。v0.1 没有持久化索引（第 2 章），版本号不用于判断是否重建，只供测试与复现检索结果。以后补回持久化索引时，再由它连同 `jieba-rs` 版本、内置词典哈希、HMM 开关组成分析器指纹，指纹不一致即重建。

## 索引

索引不落盘：每次调用重放日志时在内存中建出（第 2 章）。用 [`tantivy`](https://github.com/quickwit-oss/tantivy) 的内存索引还是自写 BM25 由实现决定，打分须符合下文「查询」。

每条记忆、每条证据各是一个文档：

| 文档 | 全文字段（`terms` + `bigrams`） | 结构化字段 |
|---|---|---|
| 记忆 | `text` | `scope`、项目标识、`status`、`epistemic`、Writer 名、当前引用的证据 id、最近一次记录或附证时间 |
| 证据 | `excerpt` | 来源类型、`cited_by` |

- 结构化字段取重放到日志末尾时的状态（被取代、撤回、附证、清除导致无据）。
- 被清除的证据与记忆不进全文字段（墓碑不被检索）。

## 查询

### 词法匹配

- `query` 经同一分析器得到两个字段的查询词元。
- 任一词元在对应字段命中即算命中（OR 语义），按 BM25 打分；`terms` 字段权重 2，`bigrams` 字段权重 1，两者相加为 `score`。
- 同分时按最近一次记录或附证时间倒序，再按 id 倒序。
- `matched_terms`：查询词元中（两个字段去重合并）在该文档出现过的，按在查询中的先后排列。智能体据此判断命中了什么、该换什么词。
- `query` 分析后没有任何词元（如只有标点）时，返回空结果。
- 不做短语查询、模糊匹配、同义词、拼音、繁简转换。

### 结构化过滤

过滤先于打分，只用结构化字段：

| 参数 | 过滤 |
|---|---|
| `scope` / `all` | `global`：作用域为全局；`project`：作用域为项目且项目在当前别名组内（`all` 为真时不限项目）；`any`：二者并集 |
| `status` | 推导出的状态在给定集合内 |
| `epistemic` | 认知状态在给定集合内 |
| `writer` | 记录这条记忆的 Writer 名相等 |
| `cites` | 当前引用的证据含该 id |
| `source_type` | 证据的来源类型在给定集合内 |
| `stale_only` | 对过滤后的全部候选做惰性核验（第 6 章），只留带可能过期标记的 |

没有 `query` 时不打分，`score` 为 0，按最近一次记录或附证时间倒序。

### 其他

- 别名组：项目过滤总是展开为整个别名组（第 1 章）。
- 截断：取前 `limit` 条后再做惰性核验（`stale_only` 除外）。
- `search` 不联网、不写日志；惰性核验只写本机的核验缓存（第 6 章）。
