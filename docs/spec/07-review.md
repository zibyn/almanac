# 7 复核

[复核（Review）](../../GLOSSARY.md)按需检查记忆库，列出待处置的问题。工具 schema 见第 3 章 `review`；会话开始注入的待复核计数见第 4 章 `context`。

## 原则

- **只读、不联网**：不写日志，不核验，可能过期只读本设备核验缓存。
- **只报告，不处置**：每项问题附建议操作，由智能体或人执行。不保存待办状态，每次调用重新计算。
- **全部确定性**：不调用 LLM，不做否定词之类的规则判断矛盾，不记录访问，不做「长期未用」检测。
- **只按需运行**：人运行 `almanac review`，或智能体在用户要求整理记忆、SKILL.md 引导时调用。不定时，写入后不自动触发。

## 范围

与 `search` 相同（第 3 章「作用域过滤」）：默认为当前项目（含别名组）加全局；`all: true` 查整库。一个问题涉及的记忆都在范围内才报告。

## 四类问题

| `type` | 报告条件 | 消除方式 |
|---|---|---|
| `multiple_successors` 多后继 | 一条记忆的**生效**后继不少于两条 | 写一条新记忆同时取代这些后继（合并），或撤回其一 |
| `similar_pair` 相似对 | 见下文 | 取代、撤回其一，或 `distinguish` 声明并存 |
| `stale` 可能过期 | 生效记忆带可能过期标记（第 6 章） | 附证、取代或撤回 |
| `unsupported` 无据 | 记忆处于无据状态（第 1 章） | 用新证据写新记忆取代它，或撤回 |

- 多后继在 v0.1 的写入路径上不会产生（第 1 章），但日志格式允许，复核必须能报告。
- 输出顺序：按上表类型顺序，同类内按涉及的第一条记忆 id 升序。

### 相似对

两条记忆构成相似对，当且仅当：

1. 都处于生效状态；
2. 作用域相同；作用域为项目时，项目在同一别名组内；
3. 相似度达到阈值（见下文）；
4. 二者之间没有[并存（Distinction）](../../GLOSSARY.md)声明。

不调用 LLM 时，矛盾就靠相似对暴露：互相矛盾的两条记忆几乎总共享词汇。是重复、矛盾还是各自成立，由智能体判断。

一条记忆被取代后，新记忆与其他记忆组成新的对，重新参与检测；旧的并存声明只对原来那两条记忆有效。

## 相似度

相似对与 `record` 响应中的 `similar` 软提示（第 3 章）**共用同一个相似度定义和同一个阈值**。阈值写在规格里，不做配置。

### 词元集合

每条记忆的正文经第 5 章分析器处理，取以下词元**去重**成一个集合：

- `bigrams` 字段的全部词元；
- `terms` 字段中来自**词段**的词元（整体与各部分）。

不用 `terms` 中的 jieba 词元，因此相似度不随 jieba 版本、词典或切词结果变化。

### 计算

相似度为两个集合的**重叠系数**：

```
sim(A, B) = |A ∩ B| / min(|A|, |B|)
```

- 取值 0 到 1。不用 BM25：其分数随语料变化，固定阈值套不住。不用 Jaccard：一条短记忆被长记忆包含（典型的更新或矛盾）时，Jaccard 偏低。
- **下限**：min(|A|, |B|) < 3 时，这一对不算相似，防止极短的记忆与大量记忆配对。
- **阈值**：sim ≥ **0.4** 算相似。

### 两处用法

- 复核：列出所有满足上文四个条件的对。
- `record` 的 `similar`（第 3 章）：在满足阈值与下限的候选中取相似度最高的至多 3 条；同分时按最近一次记录或附证时间倒序，再按 id 倒序。没有达到阈值的就为空数组，不凑数。

相似度不写入日志，也不进索引。改动本节的定义或阈值无需迁移数据，也无需重建索引。
