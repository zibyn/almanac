# 0 总览

## 定位

almanac 是给智能体用的外部长期记忆库，一人一库。它把[证据（Evidence）](../../GLOSSARY.md)和从证据中提炼出的[记忆（Memory）](../../GLOSSARY.md)分开存放：记忆会变，证据永存（除非人明确[清除（Purge）](../../GLOSSARY.md)）。

- **事实来源**：一份只追加的事件日志；记忆的状态、索引、缓存都由日志推导或可删重建（[ADR 0002](../adr/0002-event-log-is-the-source-of-truth.md)）。
- **接入**：单个 Rust 二进制，同时提供 CLI 与 MCP stdio，经宿主原生插件接入 Codex、Claude Code、Pi 等智能体（第 9 章）。
- **部署**：v0.1 只在本机内嵌运行。Server 模式与多设备接入推迟到 v0.2；写入方生成 id 与事务 id，为它留了路。
- **agentic search**：almanac 只提供确定性、可解释的查询原语：中文分词后的词法检索、结构化过滤、记忆→证据与取代链的跳转。判断哪些记忆相关、是否矛盾、该不该取代，由智能体多轮检索后完成。核心不调用 LLM，不用 embedding（[ADR 0003](../adr/0003-no-llm-or-embeddings-in-the-core.md)）。
- **轻量**：不依赖外部数据库、向量库或图数据库；存储为记忆的特性定制（第 2 章）。

## Out of scope

v0.1 不做：

- 多用户、团队共享记忆库。
- embedding、语义排序、向量库、图数据库。
- Server 模式与多设备接入（推迟到 v0.2）。
- 离线写入后的多设备合并同步。事件日志为它留了路，但 v0.1 不设计。
- 从现有记忆系统（Claude Code memory、Codex memories 等）导入。
- 写入路径上的 LLM 抽取、人工审批。

## 六个痛点的答案

| 痛点 | 答案 | 所在章 |
|---|---|---|
| 维护难 | 按需运行的只读[复核（Review）](../../GLOSSARY.md)列出多后继、可能过期、无据三类问题，只报告不处置；智能体或人用附证、取代、撤回处置；写入时相似记忆作为软提示返回，在最便宜的时候合并 | 7，3 |
| 真实性验证 | almanac 只做确定性的[核验（Source Check）](../../GLOSSARY.md)：证据摘录在来源中是否还在；推导出[可能过期（Stale）](../../GLOSSARY.md)标记，由智能体判断记忆是否仍成立 | 6 |
| 写入门槛 | 记忆必引证据，必填作用域；[认知状态（Epistemic Status）](../../GLOSSARY.md)可省略，由证据保守推出；[写入方（Writer）](../../GLOSSARY.md)自动填写；只做结构性硬检查（唯一例外：文件证据的摘录须在当前文件中），相似记忆作为软提示返回 | 1，3 |
| 遗忘与更新 | 记忆正文不可变，更新即[取代（Supersession）](../../GLOSSARY.md)，遗忘即[撤回（Retraction）](../../GLOSSARY.md)，都只追加；物理抹除只能由人发起清除 | 1，2 |
| 来源验证 | 每条证据带完整[来源（Provenance）](../../GLOSSARY.md)：来源类型、定位、时间、写入方；文件与网页证据可回查核验 | 1，6 |
| 中文支持 | 自写组合分析器（jieba-rs + 标识符拆分 + CJK bigram 兜底），每次调用由日志重放建内存索引，不落盘 | 5 |
