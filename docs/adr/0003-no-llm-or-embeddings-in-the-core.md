# 核心不使用 LLM 与 embedding，检索只做词法检索，推理交给智能体

almanac 只提供确定性、可解释的查询原语：中文分词后的词法检索、结构化过滤、记忆→证据与取代链的跳转。写入路径不调用 LLM 抽取，检索不做 embedding 或语义排序，也不依赖向量库或图数据库。判断「哪些记忆相关、是否矛盾、该不该取代」由调用它的智能体完成，智能体可以多轮检索（agentic search）。结果因此可复现、可解释，核心也能保持单个二进制、离线可用。

## Considered Options

- **写入路径 LLM 抽取**（如自动从对话提炼记忆）：降低写入成本，但引入不可复现的结果、模型依赖和凭据，且抽取错误会悄悄进入记忆库。
- **embedding 语义检索 / 向量库**：同义改写召回更好，但需要模型和向量存储，排序不可解释；宿主智能体本身就能改写查询词多轮检索来弥补。

## Consequences

- 中文召回质量完全取决于分析器（jieba-rs + 标识符拆分 + CJK bigram 兜底），索引记录分析器指纹以便重建。
- 写入软提示和复核里的「相似」也只能用词法相似度。
- 将来如需语义检索，应作为可重建的派生索引加在旁边，不改变日志和工具语义。
