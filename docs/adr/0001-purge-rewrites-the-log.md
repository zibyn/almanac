# 清除通过重写事件日志实现，而非加密粉碎

事件日志原则上只追加，但敏感内容必须能被物理抹去，包括 Evidence 原文和复述了它的 Belief 正文。我们选择由人发起的 Purge（仅 CLI，MCP 不暴露）直接重写日志：把被清除的证据或信念正文替换为 Tombstone（标识、清除时间、原因、执行人；不留原文哈希，以免短内容被穷举确认），随后重建索引。v0.1 一人一库、Server 模式为在线连接且不做离线合并，重写只发生在一处，不存在分布式一致性问题。

## Considered Options

- **加密粉碎（crypto-shredding）**：每条证据独立密钥加密，清除即销毁密钥，日志保持严格只追加。代价是逐条密钥管理、库文件无法直接阅读或 grep，违背「轻量、可解释」。若将来引入离线多设备合并（日志副本散落多处），应重新评估此方案。

## Consequences

- 「日志只追加」的不变式有唯一例外：Purge。其他任何操作都不得重写日志。
- 清除证据时，CLI 列出引用它的所有信念（含取代链历史版本），由人逐条决定是否一并清除。
- 证据全部被清除的 Belief 推导为 Unsupported，无需额外事件。
